## CDRAM pool (ebc1b4a, in dev) vs hwdec_gxm.c GC list

No new use-after-free: blocks return to the pool only when the last AVBuffer ref
drops (including the 3-deep GC list's), the same point the old code freed them.
mpv 0.36 doesn't remap on redraw (`vimg->id == id`), so the 3 slots are distinct.
Pre-existing risk: no GPU fence after `sceGxmEndScene(ctx, NULL, NULL)`; if the GPU
lags > 3 frames the pool turns an invisible stale read into a visible glitch.
Minor: blocks released after `uninit_avctx` linger in the pool (<= 8, ~12 MB at
720p); hwdec `uninit()` unrefs without `sceGxmUnmapMemory`. Draft comment not posted.

## Background downloads (branch `vita-bgdl-plugin`)

Symptom: a download finished in LiveArea won't play in Switchfin.
Most likely cause: **Original** quality bypasses Jellyfin's transcode, and the
Vita FFmpeg build only decodes h264 video and aac/ac3/flac/mp3 audio (no HEVC,
VP9, AV1, E-AC3, DTS, TrueHD, Opus). bgdl bookkeeping (filePath, marker, rename,
completion check) reads correct.

Checks:
1. Episode codecs in Jellyfin Media Info
2. File size of `ux0:data/Switchfin/downloads/<itemId>/video.<ext>` vs server
   (tiny = error page; different = HEAD->GET probe corruption)
3. Same episode with Background Downloads off: if that fails too, it's codecs
4. `ux0:data/switchfin_bgdl_plugin.txt`: `export ... rename ... = 00000000`

Likely fix if codecs: on PSV, warn/disable Original when the source isn't
H.264 + aac/ac3/mp3/flac <= 720p, or default Vita downloads to 720p transcode.
